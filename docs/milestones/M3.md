# M3 — Survival core: status

**State: code complete and verified without Unity; not yet run in Unity or on an iPhone.**
Everything below runs on the engine-independent core and is covered by automated tests, including
the milestone's automated exit criterion (the gather → craft → cook → die → respawn-at-bedroll loop
surviving a server restart, end to end over the network). The Unity client and server compile against
Unity 6000.3 but haven't been executed, so the **manual demo on a device is not done** (see "Open items").

**End-to-end network tests** (real `ClientSession`s against `ServerHost` on the simulated network):
joining delivers map, inventory, own state and nearby chunks; swinging at a tree fills the client's
inventory; the crafting queue and result reach the client; a campfire placed by one player is seen by
another, opened, filled, lit and cooks, and the cooked food is eaten; death leaves a body others see
and the player respawns at their bedroll; chunks load and unload as players move; a different content
version is refused; and **the whole loop survives a server restart** (inventory, position, bedroll and
campfire, depleted nodes and world time all come back, and the player gets their character back).

**Test totals:** 201 tests in `sim/Kindling.Sim.Tests` (the same files Unity's Test Runner compiles),
7 in `sim/Kindling.Server.Tests`.

## Load tests (real UDP, `sim/loadtest.sh`)

Same setup as M1: one 4 vCPU cloud container runs the dev server (now with the survival world, SQLite
saves every 10 s) and all bots; 30–60 ms delay and 2% loss in each direction; 60 s. Half the bots
wander, half play (walk to trees, chop, craft and place a campfire, eat, drink). Unlike M1, bots spread
over the map, so they don't all see each other. Raw results: [M3-loadtest/](M3-loadtest/).

## Changes from the plan (recorded)

- **Content is JSON, not ScriptableObjects** ([ADR 0008](../adr/0008-content-as-json-data.md)).
- **Save schema adapted**: blobs instead of relational containers/items; the Unity server uses a file
  store, the .NET server SQLite ([ADR 0009](../adr/0009-persistent-world-model.md)).
- **The server sends the static map** to clients; **characters sleep on disconnect** instead of M1's
  120 s resume grace ([ADR 0009](../adr/0009-persistent-world-model.md)).
- **Hotbar at the top center** of the touch layout (bottom center doesn't fit between the joystick
  and the action buttons at the 44-point minimum); the HUD editor (later) will let players move it.
- **No animals yet** (they need AI): the cookable food is mushrooms; meat, hide and bone wait for animals.
- **No Forge Bench / iron tools / blueprint learning yet**: iron bars can be smelted but not used;
  recipes already carry a knowledge flag. These come with M5 content.

## Known limitations (planned)

- **Deployables don't block movement**, and **depleted trees and rocks keep their collision** (shown
  as stumps/rubble). Dynamic collision comes with building in M4.
- Thirst's stamina penalty isn't implemented yet.
- Sleeper protection: `protectedInClaim` protects nobody until claims exist (M4); nothing can damage
  players until combat (M5).
- Chunk snapshots aren't compressed and player snapshots aren't delta-compressed.
- Dev auth only (the account id is a device id); join tickets come with the M2 client work.
- The Unity dedicated server saves to a single file (fine for small servers); see ADR 0009 for making
  the .NET server the official one.
