# 14 — Milestone Roadmap

## 1. Assumptions behind the estimates
- **Team:** one full-time developer (you) working with me, plus bought or contracted art and audio
  from M6 onward.
- **Estimates are calendar weeks with ±40% uncertainty.** They get re-estimated at the end of every
  milestone using real data.
- **Every milestone ends with a demo on a real iPhone** (or, for backend-only parts, working endpoints
  with tests). A milestone isn't "done" until its exit criteria are shown working. Partial work is
  reported as partial.
- Order matters: networking and authority come first, because adding them later means rewriting
  everything.

## 3. Milestones in detail

### M0 — Foundations and toolchain (2 weeks)
**Deliverables**
- Monorepo skeleton per [12](12-folder-structure.md): pnpm workspace, TS configs, lint/format, `.gitattributes` (LFS), `.gitignore`, CONTRIBUTING, ADRs 0001–0004 (engine, netcode, backend, persistence).
- Docker Compose dev stack (PostgreSQL, Redis). `apps/api` with config loading, structured logging, `/health`, error handling, OpenAPI generation; `packages/db` with Drizzle and a first migration; Vitest + Testcontainers wired up.
- Unity: `game/` with `Packages/manifest.json`, the asmdef layout, Boot scene, URP tier assets, an editor bootstrap script (you open the project once in Unity 6 LTS to generate `ProjectSettings`, then commit it). FishNet vendored at a pinned version.
- `sim/` .NET test project linked to the pure-C# sources.
- CI: `ci-ts.yml`, `ci-sim.yml`, `ci-unity.yml` (GameCI, after the license secret is added).
**Exit criteria:** `docker compose up` + `pnpm test` pass; the Unity project opens with no errors and builds an empty iOS app (on your Mac) and a Linux dedicated server; CI is green.

### M1 — Netcode and movement vertical slice (4–5 weeks)
**Deliverables**
- FishNet integration behind `Kindling.Net`; Tugboat UDP with IPv6 dual-stack; dedicated server build and startup flow (temporary dev-only auth, clearly marked).
- Kinematic first-person controller with **client-side prediction and reconciliation**; remote interpolation; walk, sprint, crouch, jump.
- **Touch controls:** floating joystick, look zone, jump/crouch/sprint (with sprint lock), attack/interact placeholders, multi-touch ownership, safe areas, sensitivity settings.
- Greybox test map (500 m), generated by editor tools.
- Headless **bot clients** + `tools/loadtest` launcher; server tick/bandwidth metrics.
- Resume-token reconnect after the app goes to the background.
**Exit criteria:** 2+ real iPhones + 30 bots on a Linux server (cloud VM) play smoothly; prediction corrections are rare and invisible on Wi-Fi and LTE; measured tick time, bandwidth and prediction error are recorded in an ADR.
**Decision gate:** confirm FishNet (or switch to Mirror now, before more is built on it).

### M2 — Accounts, backend core, server registry, join tickets (4–5 weeks)
**Deliverables**
- Auth: register/login/email verification/password reset, Sign in with Apple, refresh rotation, rate limits, App Attest (as a signal).
- Profiles, cloud saves (settings + HUD), `/v1/bootstrap` (version gate + maintenance + config skeleton).
- Server registry, server tokens, **server link** (hello/heartbeat/commands skeleton), Redis live index, `GET /v1/servers`, **join tickets** (Ed25519, JWKS) + reservations; the game server verifies tickets (the dev auth from M1 is removed).
- Unity: login screens, Sign in with Apple bridge, server browser UI (filters, ping), join flow, "update required" and maintenance screens.
- **Web console shell:** staff login with TOTP, RBAC framework, audit middleware, staff management page, basic audit log viewer.
- Deploy a `dev` environment (one VM) with Caddy and TLS.
**Exit criteria:** on an iPhone, sign in with Apple → see the live server list → join with a ticket. A forged, expired or reused ticket is rejected (shown by automated tests). A staff user signs in with TOTP, and the action appears in the audit log.

### M3 — Survival core (6–7 weeks)
**Deliverables**
- Content pipeline: ScriptableObject definitions, stable IDs + lock file, validator, `content-export.json`.
- Item system, **authoritative inventory**/hotbar/equipment with owner-only deltas; inventory UI for touch.
- Gathering: trees, rocks, ore nodes with tool tiers, sweet spots, **chunk bitset replication**, respawn.
- Crafting (queue, stations: hand, Crude Bench, Campfire, Smelter), cooking, smelting.
- Survival stats (health, hunger, thirst, warmth, stamina) + status effects; food and water sources.
- Death → body container → respawn (beach or bedroll); downed state; sleepers (all 3 modes).
- **Chunk replication** for deployables, containers and dropped items; loot spawners + loot tables.
- Day/night cycle (server-authoritative).
- **SQLite persistence** (dirty tracking, background writer, checkpoints, backups) + restore on startup.
**Exit criteria:** a 30-minute play session covering gather → craft tools → cook food → die → respawn
at a bedroll; restart the server → the world, inventories and characters are restored exactly
(automated persistence round-trip tests + a manual demo).

### M4 — Building and base ownership (6 weeks)
**Deliverables**
- Building plan and mallet; sockets/grid; ghost preview with reasons; touch build UX.
- Pieces (foundations, floors, walls, doorways, windows, stairs, roofs) + tiers + upgrade/repair/demolish.
- **Stability** (incremental + Burst job), collapse.
- **Claim Beacon:** authorization, build blocking, upkeep, decay.
- Doors, Tumbler Lock (keys), Keypad Lock (code + authorized list), storage chests, beds, workbenches.
- Combined building meshes per chunk (performance); placement validation fully on the server.
**Exit criteria:** build a 2-story stone base with doors and locks on an iPhone; a second player can't
build, open or loot it; a server restart keeps everything; a 2 000-piece stress base holds the tick and
FPS budgets.

### M5 — Combat and raiding (5 weeks)
**Deliverables**
- Melee, bows, crossbow, revolver, shotgun, lever rifle; projectiles; **lag compensation** (hitbox history, rewind cap).
- Damage model (hitboxes, armor, bleeding), hit markers, haptics, aim slowdown (touch).
- Raiding: damage types vs. tiers, Fire Bottle, Crude Breach Charge, Breach Charge, container loot drop rule, claim activity log, **offline raid protection** settings, raid windows.
- Server-side anti-cheat checks (movement, fire rate, line of sight, intent rate limits) + flags.
**Exit criteria:** a 2v2 fight + raid on iPhones over LTE feels fair (subjective playtest + measured
hit-registration error); exploits found during testing are logged and fixed; raid alerts reach the
activity log (push comes in M7).

### M6 — World v1 and performance tiers (7–8 weeks)
**Deliverables**
- The 2 km × 2 km launch map: terrain tiles, biomes (forest, mountains, rivers, lakes, beaches, highlands), caves, 8–12 points of interest, hidden caches, blight zones, hazards (cold, drowning, falling).
- Weather state machine (clear/overcast/fog/rain/storm) with gameplay effects.
- Wildlife AI (deer, boar, wolf, bear): server-simulated, sleeps when no players are near.
- Grab system (pick up / carry / place / throw) with physics limits; salvage crates.
- **Graphics tiers** (Low/Medium/High), auto-detection, thermal scaling, LODs, impostors, occlusion, texture streaming, shader warm-up; memory budgets enforced.
- First production-quality art pass for the core set (artist involvement starts).
**Exit criteria:** 30 FPS on iPhone 11 (Low) and 60 FPS on a recent iPhone (High) across the map, in
an agreed benchmark route; no memory warnings in a 60-minute session; **50 bots in a 24-hour soak**
with p99 tick ≤ 25 ms and memory growth < 5%.

### M7 — Social, moderation, admin core → Closed alpha (5 weeks)
**Deliverables**
- Friends, requests, blocks, presence, parties, join a friend; realtime WebSocket; push notifications (raid alerts, invites).
- Chat (proximity/team/global) with filtering; gestures; signs; reports with server evidence.
- Sanctions (global + server), text filter management.
- Console: dashboard, player search and detail, sanctions, reports queue, **inventory moderation via the server link**, filters.
- Quick Play matchmaking with reservations and party placement.
- Voice chat **go/no-go decision** (prototype if go).
- TestFlight internal + small external group; Sentry crash reporting live.
**Exit criteria:** 10–20 external testers play for a week on staging; a moderator handles a report end
to end (report → evidence → ban → audit trail) from a phone browser; Quick Play puts a party of 3
together on one server.

### M8 — Community servers and owner portal (4 weeks)
**Deliverables**
- `kindling-host` supervisor (Docker image + standalone), signed build manifests, verification, auto-update with rollback, scheduled restarts.
- Server config schema + validation; password-protected servers; whitelist mode; wipe scheduling.
- Owner Portal: create server/token, settings, players, bans, staff, live logs, controls, updates, audit.
- Reachability probe, listing states, verification and delisting in the staff console; server browser integration (community filters, "outdated" state).
- Hosting guide in `docs/hosting/`.
**Exit criteria:** someone else follows the guide on a fresh Linux VPS, their server appears in the
browser, players join, the owner kicks or bans and edits an inventory, and a newly published build
installs itself with a countdown (and rolls back when a broken build is published on purpose).

### M9 — Live ops, versions, analytics, season framework (4–5 weeks)
**Deliverables**
- Version management (client versions, policy, server builds, content releases with staged rollout + rollback).
- Remote config with targeting + history; maintenance (scheduled/immediate); announcements; events (multiplier and world events).
- Analytics ingestion + nightly rollups + dashboards; stats leaderboards; DB/Redis/queue monitoring pages; full audit log viewer + export.
- **Season framework:** SeasonDef, biome overrides, weather profiles, Addressables remote groups, challenges + progress + rewards, entitlements.
**Exit criteria:** from the console (on a phone): publish an announcement, schedule maintenance, start
a 2× gather event on official servers, force an update on an old build, roll out a test season pack to
10% and roll it back. Every action is visible in the audit log.

### M10 — Beta hardening → Open TestFlight beta (6 weeks)
**Deliverables**
- **Load test:** 75–100 bots + real devices on staging hardware → official player cap set; API load test (k6) at 10× the expected beta traffic.
- **Security review:** threat model pass, dependency audit, auth/session tests, server-link fuzzing, rate-limit tuning, backup restore drill.
- Performance pass on all tiers; battery and thermal test (60 minutes); network-loss and NAT64 tests.
- HUD editor polish, accessibility options, onboarding/tutorial, settings complete.
- Legal/compliance: privacy policy, terms, community server rules, age rating, App Privacy label, account deletion verified.
- Production infrastructure: monitoring, alerts, runbooks, official fleet (one region) with canary deploys.
**Exit criteria:** an external TestFlight beta runs for 2+ weeks with crash-free sessions ≥ 99.5%,
no open critical security issues, and alerts and runbooks tested in a simulated incident.

### M11 — App Store launch (3–4 weeks)
Store listing (screenshots, preview video, description), App Review submission (with time for a
resubmission), phased release, launch-day runbook (scaling plan, on-call), first live event scheduled,
post-launch patch window reserved.
**Exit criteria:** the app is live; dashboards are green; the first-week retention and crash numbers
have been reviewed.

### M12 — Winter Update (6–8 weeks, first post-launch season)
Content and schedule as in [11](11-seasonal-content-and-winter-update.md) — winter content and
performance improvements. Starts at S − 12 weeks.

## 4. Working method per milestone
1. **Plan:** I break the milestone into tasks/issues with acceptance criteria. You review.
2. **Build:** I implement on feature branches with tests. Backend and web are tested in this
   environment. Unity code is compiled and tested through CI.
3. **Device check:** you run the build on iPhones and send logs, screenshots and profiler captures. I fix.
4. **Demo + review:** the exit criteria are shown working. Gaps are reported plainly and either carried
   over or re-planned.
5. **Re-estimate** the remaining roadmap with real numbers.

## 5. What could change the plan
- The M1 gate fails (netcode does poorly on cellular) → switch library or change the approach early.
- M6 shows iPhone 11 can't reach 30 FPS → raise the minimum device or cut visual scope.
- Art is late or not available → keep greybox longer; launch scope is cut by content, not by systems quality.
- App Review issues (UGC, voice, purchases) → compliance is checked before every submission ([10 §8](10-ios-distribution-and-liveops.md#8-app-store-compliance-checklist-checked-before-every-submission)).
